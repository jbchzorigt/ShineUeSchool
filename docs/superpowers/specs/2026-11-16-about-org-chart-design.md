# "Бидний тухай" — байгууллагын бүтцийн диаграм — дизайн

Огноо: 2026-11-16. Төлөв: батлагдсан (2026-11-16), хэрэгжүүлэх төлөвлөгөө бичих шатанд. Суурь: "Бидний тухай" хуудас (`docs/superpowers/specs/2026-09-23-about-page-design.md`, `backend/app/about/`, `frontend/src/components/about/`, `/admin/about`).

## 1. Зорилго ба шалтгаан

`/about` хуудсанд сургуулийн удирдлагын бүтцийг **хэн хэнд харьяалагддаг**-аар нь модон диаграм болгон харуулна: хүн бүр зураг, нэр, албан тушаалтай карт; тэнхимүүд харьяалагдах удирдлагынхаа доор. Харьяаллыг менежер `/admin/about`-аас өөрөө удирдана. Хөдөлгөөн GSAP, загвар Tailwind (хэрэглэгчийн шаардлага).

Одоогийн байдал: удирдлагын гишүүнд зөвхөн 1–10 `level` (түвшин) бий, хэн хэнд харьяалагдах холбоос байхгүй; тэнхим удирдлагатай холбогдоогүй. Хуудсанд "Сургуулийн хамт олон" хэсэг (`LeadershipChart.tsx` — нэр нь chart боловч гүйдэг marquee картууд) байна.

## 2. Хэрэглэгчийн шийдвэрүүд

- Диаграмд хүмүүсийн **нэр, зураг, албан тушаал** ба **тэнхимийн харьяалал** гарна.
- Харьяаллыг **админаас** удирдана.
- Тэнхимийн дэлгэрэнгүй — **сонголт A**: тэнхим нэг карт (тэнхимийн нэр, эрхлэгч, багшийн тоо), дарахад багш нарын жагсаалт нээгдэнэ. Багшид зураг нэмэхгүй; зураг зөвхөн удирдлагад.
- "Сургуулийн хамт олон" marquee-г **диаграмаар солино** (Claude-ийн санал, хэрэглэгч эсэргүүцээгүй).
- Бүтээх арга — **1-р арга**: HTML салаа жагсаалт (`ul > li`) + Tailwind шугам, GSAP-аар түвшин түвшнээр нээгдэх.

## 3. Хамрах / хамрахгүй / бүтэлгүйтэл

Хамрах:
- Backend: `about_leaders.parent_id`, `about_departments.leader_id` (migration 0023), API-д нэмэх, шалгалт, тест.
- Админ: удирдлагын гишүүнд "Харьяалагдах дээд албан тушаалтан", тэнхимд "Харьяалагдах удирдлага" сонголт.
- Нийтийн `/about`: шинэ `OrgChart` компонент (MN, EN), marquee хэсгийг хуудаснаас авах.

Хамрахгүй:
- Багш нарын зураг, хувийн хуудас; чирж/томруулдаг (pan/zoom) зураг; диаграмыг PDF/зураг болгон татах.
- `level` баганыг устгах (админы бүлэглэлт, эрэмбэд хэвээр хэрэглэгдэнэ).
- Нэг хүн хоёр дээд албан тушаалтанд харьяалагдах (matrix) бүтэц — нэг л `parent_id`.
- Доорх "Тэнхимүүд" хэсгийг өөрчлөх (хэвээр үлдэнэ).

Бүтэлгүйтэл гэж тооцох (ажилласан ч):
- Гар утсанд диаграм хэвтээ чиглэлд дэлгэцээс гарч, хуудас бүхэлдээ хажуу тийш гүйдэг болох.
- Хөдөлгөөн дуусаагүй эсвэл тоглогдоогүйгээс картууд үл үзэгдэх хэвээр үлдэх (ScrollSmoother дор ScrollTrigger ажилладаггүй — `Reveal.tsx`-ийн тайлбарыг үз).
- Админ мөчлөг (A → B → A) үүсгэж хуудсыг гацаах эсвэл гишүүнийг алга болгох.
- Дэлгэц уншигчид бүтэц уншигдахгүй (зөвхөн зураас, div).

## 4. Аргууд (сонгогдсон: 1)

1. **HTML мод + Tailwind шугам (сонгосон).** Салаа `ul > li`, холбох шугам нь span/pseudo элемент. GSAP: шугам `scaleY`/`scaleX`-ээр ургаж, картууд түвшин түвшнээр гарна. Гар утсанд босоо, зүүн шугамтай мод. Layout хэмжих JS байхгүй тул resize, тэнхим нээх үед эвдрэхгүй; семантик жагсаалт.
2. HTML карт + SVG муруй шугам. Илүү гоё "зурагдах" эффект, гэхдээ картын байрлалыг JS-ээр хэмжиж resize/нээх бүрт дахин зурах — эмзэг. Татгалзсан.
3. react-flow / d3-hierarchy сан. Pan/zoom canvas, сайтын загварт нийцэхгүй, хүнд, хэрэглэгч GSAP + Tailwind гэсэн. Татгалзсан.

## 5. Өгөгдөл ба API

Migration `0023_about_org_chart.py` (down_revision `0022`):
- `about_leaders.parent_id` Integer nullable, FK → `about_leaders.id` **ON DELETE SET NULL**, index.
- `about_departments.leader_id` Integer nullable, FK → `about_leaders.id` **ON DELETE SET NULL**, index.
- Өгөгдлийн анхны утга (зөвхөн `parent_id IS NULL` мөрүүдэд, нэг удаа): `level = n` гишүүний `parent_id` = `level`-ээр түүнээс өмнөх хамгийн ойрын түвшний эхний гишүүн (`order`, `id`-аар). Ингэснээр одоогийн өгөгдөл "Захирал → Гүйцэтгэх захирал → (Дэд захирал, Менежер, Үүсгэн байгуулагч)" болж эхэлнэ; менежер дараа нь засна. Тэнхимд анхны утга өгөхгүй (null). *(Claude-ийн шийдвэр: хоосон харьяалалтай 5 тусдаа мод гарахаас сэргийлнэ.)*

Схем:
- `LeaderOut` + `parent_id: int | None`; `DepartmentOut` + `leader_id: int | None` (нийтийн ба админы хариунд хоёуланд).
- Үүсгэх: `POST /leaders/` multipart-д `parent_id` Form (заавал биш; хоосон/байхгүй = null). `DepartmentIn` + `leader_id: int | None = None`.
- Засах: `LeaderPatch.parent_id`, `DepartmentPatch.leader_id` — `exclude_unset` ашиглаж, илгээгээгүй бол хөндөхгүй, `null` илгээвэл арилгана.

Шалгалт (талбарын алдаа `FieldError`, монгол мессеж):
- `parent_id`: байгаа гишүүн байх; өөрөө биш; мөчлөг үүсгэхгүй (шинэ эцгээс дээш `parent_id`-аар явахад өөрийгөө олохгүй байх).
- `leader_id`: байгаа гишүүн байх.
- Гишүүн устгахад түүний шууд доод гишүүд ба тэнхимүүд DB-ээр `NULL` болно (дээд талдаа шилжихгүй — хамгийн энгийн, урьдчилан таамаглаж болох). Админы устгах confirm-д "N гишүүн, M тэнхим харьяалалгүй болно" гэж анхааруулна.
- `PUT /leaders/order/` (level, order өөрчлөх) `parent_id`-г хөндөхгүй.

## 6. Админ

- `LeaderDialog`: "Харьяалагдах дээд албан тушаалтан" `Select` — "— Хамгийн дээд (харьяалалгүй)" + бусад гишүүд (`нэр — албан тушаал`). Засах үед өөрийгөө ба өөрийн доод гишүүдийг жагсаалтаас хасна (мөчлөгийг UI-д ч хаана; backend эцсийн хамгаалалт).
- `LeaderList` мөр бүрт харьяалал товч текстээр ("→ Захирал Цэрэндолгор" эсвэл "Хамгийн дээд").
- Тэнхимийн хуудас: тэнхим бүрт "Харьяалагдах удирдлага" `Select` ("— Харьяалалгүй (диаграмд гарахгүй)" + гишүүд). Байрлал (inline засах мөр эсвэл баруун талын багшийн самбарын толгой) — builder шийднэ.
- Харьяалалгүй тэнхимийн жагсаалтын мөрөнд "диаграмд гарахгүй" гэсэн жижиг тэмдэг.

## 7. Нийтийн диаграм

Байршил: `/about`, "Сургуулийн түүх"-ийн дараа, "Тэнхимүүд"-ийн өмнө — `LeadershipChart`-ийн оронд. `LeadershipChart.tsx`-ийг устгана (өөр газар ашиглагддаггүй; `ProgramCard.tsx` дахь дурдлага зөвхөн тайлбар). Гарчиг ба тайлбар толь бичгээс (`about.orgTitle`, `about.orgLead` — MN, EN), хуучин `teamTitle/teamLead/teamAria` ашиглагдахгүй бол хасна.

Модыг угсрах — цэвэр функц (`frontend/src/lib/org-tree.ts`, node test-тэй):
- Оролт: `leaders` (API эрэмбээр: level, order, id), `departments` (order, id).
- Үндэс: `parent_id` null эсвэл жагсаалтад байхгүй гишүүн. Хүүхдүүд эцгийнхээ доор API эрэмбээр; тэнхимүүд гишүүдийн дараа, тэнхимийн эрэмбээр.
- Мөчлөгөөс хамгаалалт (өгөгдөл ямар ч байсан хуудас гацахгүй): аль хэдийн зочилсон гишүүнийг дахин оруулахгүй; мөчлөгт орсон гишүүдийг үндэс болгоно — гишүүн хэзээ ч алга болохгүй.
- `leader_id` нь null эсвэл байхгүй гишүүн рүү заасан тэнхим диаграмд гарахгүй (доорх "Тэнхимүүд" хэсэгт хэвээр).
- Олон үндэс бол зэрэгцээ модод.

Карт:
- Удирдлага: зураг (байхгүй бол navy дэвсгэр дээр эхний үсэг — marquee-тэй ижил), нэр, албан тушаал (`?lang`-аар). Үндэс карт бусдаасаа арай том.
- Тэнхим: өөр төрх (зураггүй), тэнхимийн нэр, эрхлэгч (`is_head` — хэд хэд бол бүгд), "N багш". Багштай бол товч (`button`, `aria-expanded`, `aria-controls`) дарахад багш нарын жагсаалт (нэр, role, эрхлэгч тэмдэг) нээгдэж/хаагдана; GSAP-аар өндөр/opacity анимаци. Багшгүй бол товч байхгүй, "Багш нарын мэдээлэл удахгүй."

Layout:
- `md` ба түүнээс өргөн: хэвтээ мод (эцэг дээр, хүүхдүүд доор хэвтээ мөрөнд), CSS шугам. Мод контейнерээс өргөн бол **зөвхөн диаграмын контейнер** `overflow-x-auto` (хуудас хажуу тийш гүйхгүй), багтвал голлуулна.
- `md`-ээс нарийн: босоо, догол мөртэй мод — хүүхэд бүр эцгийнхээ доор зүүн талын босоо шугамтай, картууд бүтэн өргөнтэй.
- Семантик: `ul`/`li` салаа жагсаалт, хэсэгт `aria-labelledby`; шугамууд `aria-hidden`.

Хөдөлгөөн (GSAP, `@/components/site/gsap`):
- Хэсэг дэлгэцэнд орох үед **нэг удаа** тоглоно — `IntersectionObserver` (Reveal-тэй ижил шалтгаан: ScrollSmoother дор ScrollTrigger ажилладаггүй).
- Timeline: үндэс карт → доошоо шугам ургана → хэвтээ салаа шугам голоос хоёр тийш → дараагийн түвшний картууд stagger → … гүнээр давтана. Нийт ~2 сек орчим.
- `prefers-reduced-motion`: анимацигүй, бүх зүйл шууд харагдана. JS ачаалагдаагүй/алдаа гарсан ч картууд харагдана (эхний төлөв нь CSS-ээр нуугдахгүй; GSAP `set`-ээр нууна).
- Тэнхим нээх анимаци хэрэглэгчийн үйлдлийн хариу — мөн reduced motion үед шууд.

- Тэнхимийн харьяаллын select-ийн админд байрлах газар.

- Олон эрхлэгчтэй тэнхимийн картын харагдах байдал.

## Ажлын журам

Commit, push хийхгүй — хэрэглэгч тухайн үед хэлэх хүртэл. Production сервер (`.server/`) дээр migration 0023 нь backend-ийг дахин build хийхэд автоматаар ажиллана; frontend-ийг push хийхээс өмнө серверийн backend-ийг шинэчилнэ (шинэ талбаргүй API-д frontend унахгүй байхаар `parent_id`/`leader_id` байхгүйг null гэж үзнэ).
